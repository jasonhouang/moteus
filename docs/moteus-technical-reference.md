## 1. 项目概述

### 1.1 项目定位

moteus 是由 mjbots Robotic Systems LLC 开发的开源无刷伺服执行器系统,提供从 PCB 设计、固件到客户端库的完整解决方案,面向机器人关节执行器应用。

### 1.2 硬件平台

项目支持四个硬件型号,均采用 STM32G474 MCU (ARM Cortex-M4F, 170MHz):

| 型号 | 电压范围 | 峰值功率 | 重量 | 持续相电流(冷却) | 峰值相电流 | 尺寸 |
|------|---------|---------|------|-----------------|-----------|------|
| **r4.11** | 10-44V | 900W @ 30V | 14.2g | 32A | 100A | 46×53mm |
| **c1** | 10-51V | 250W @ 28V | 8.9g | 14A | 20A | 38×38×9mm |
| **n1** | 10-54V | 1.3kW @ 36V | 14.6g | 26A | 100A | 46×46×8mm |
| **x1** | 10-54V | 1kW @ 36V | 23.8g | 62A | 120A | 56×56×10mm |

### 1.3 控制性能

- **控制频率**: 15-60kHz PWM 切换率 (取决于硬件版本)
- **通信**: 5Mbps CAN-FD 总线
- **位置精度**: 14-bit 磁编码器 (AS5047P, 0.022°)

### 1.4 项目结构

```
moteus/
├── fw/          # 固件源码 (C++, 基于 mbed)
├── hw/          # 硬件设计
│   ├── controller/r4.11/  # Eagle CAD 设计
│   ├── c1/                # KiCad 设计
│   ├── n1/                # Eagle CAD 设计
│   └── x1/                # KiCad 设计
├── lib/         # 客户端库 (Python / C++ / Rust)
├── utils/       # 诊断工具 (moteus_tool.py, tview.py)
├── tools/       # Bazel 构建配置
└── docs/        # 文档
```

### 1.5 开源许可

硬件设计和固件均基于 Apache 2.0 许可证发布。成品板可通过 mjbots.com 购买。

## 2. 传感器系统

moteus 的传感器系统围绕电机换相和输出位置反馈两个核心需求设计。

### 2.1 位置/角度传感器

位置传感器是系统中最关键的组件,承担两个不同但相关的职责:

- **换相 (Commutation)**: 确定定子与转子之间的电气关系,以正确施加力矩
- **输出反馈 (Output)**: 测量输出轴的位置和速度,以跟踪指令轨迹

#### 2.1.1 板载编码器

所有型号均集成 **AS5047P** 14-bit 磁编码器,通过 SPI 接口读取:

| 参数 | 规格 |
|------|------|
| 分辨率 | 14-bit (16384 counts/rev) |
| 接口 | SPI (最高 10MHz) |
| 安装方式 | 轴上 (on-axis) |
| 最大转速 | 28,000 RPM |
| 精度 | ±0.05° (典型) |
| 气隙 | 1-2mm |

#### 2.1.2 外部编码器支持

通过两个辅助端口 (AUX1/AUX2),可连接多种外部编码器:

| 编码器 | 接口 | 安装方式 | 性能等级 | 适用场景 |
|--------|------|---------|---------|---------|
| AS5047x | SPI | 轴上 | ★★★ | 标准应用 |
| AS5048B | I2C | 轴上 | ★★ | 低成本方案 |
| AS5600 | I2C | 轴上 | ★ | 最低成本 |
| AksIM-2 | RS422 | 离轴 | ★★★★★ | 高精度工业应用 |
| CUI AMT21x | RS422 | 轴端 | ★★★★ | 中空轴应用 |
| CUI AMT22x | SPI | 轴端 | ★★★★ | 轴端安装 |
| MA600 | SPI | 轴上/离轴 | ★★★★ | 灵活安装 |
| MA732 | SPI | 轴上/离轴 | ★★★ | 通用 |
| BiSS-C | RS422 | 轴上/离轴 | ★★★★ | 工业标准 |
| iC-PZ | SPI | 离轴 | ★★★★★ | 超高精度 |
| RLS Orbis | SPI | 离轴 | ★★★★ | 紧凑型 |
| 正交编码器 | 正交 | 可变 | 可变 | 增量式 |
| 正弦/余弦 | 模拟 | 可变 | ★ | 传统方案 |
| 霍尔传感器 | GPIO | 可变 | — | 低成本换相 |

系统最多支持 3 个编码器源同时配置,可分别用于换相和输出反馈。

### 2.2 电流传感器

电流检测用于磁场定向控制 (FOC) 和过流保护:

| 组件 | 功能 | 规格 |
|------|------|------|
| **采样电阻** | 相电流分流 | 低阻值精密电阻 (毫欧级) |
| **电流放大器** | 信号放大 | 差分放大器,配合 PWM 同步采样 |
| **三相检测** | U/V/W 相电流 | 通过 ADC1/2/3 同步采样 |

采样时序与 PWM 同步,在 PWM 导通期间稳定窗口内完成 ADC 转换,避免开关噪声干扰。

### 2.3 电压传感器

| 监测点 | 方法 | ADC 通道 |
|--------|------|---------|
| **母线电压** | 电阻分压 + ADC | ADC4/5 |
| **滤波电压** | 数字滤波 | 软件实现 |

提供三级电压监测:
- `bus_V`: 实时母线电压
- `filt_bus_V`: 滤波后母线电压
- `filt_1ms_bus_V`: 1ms 平均电压

### 2.4 温度传感器

| 监测点 | 传感器类型 | 参数 |
|--------|-----------|------|
| **板载温度** | NTC 热敏电阻 | B=4050, R=10kΩ |
| **电机温度** | NTC 热敏电阻 | 可配置 (默认 10kΩ) |

温度计算采用查表法 (32 点 LUT),通过 ADC 原始值进行线性插值,计算效率高且精度足够。

### 2.5 传感器配置架构

编码器配置分三个阶段:

1. **辅助端口配置**: 定义引脚功能 (SPI/I2C/UART/Quadrature 等)
2. **编码器源配置**: 在 `motor_position.sources` 中定义最多 3 个源
3. **输出配置**: 指定哪个源用于换相,哪个源用于输出位置反馈

关键参数:
- `motor_position.commutation_source`: 换相使用的编码器源 (通常为源 0)
- `motor_position.output.source`: 输出位置使用的编码器源
- `motor_position.rotor_to_output_ratio`: 转子到输出的减速比

## 3. MCU 外设资源

### 3.1 MCU 型号

所有型号均使用 **STM32G474CEU6**:

| 参数 | 规格 |
|------|------|
| 内核 | ARM Cortex-M4F |
| 主频 | 170 MHz |
| Flash | 512 KB |
| SRAM | 128 KB |
| 封装 | UFQFPN-48 (7×7mm) |
| 工作温度 | -40°C ~ 85°C |

### 3.2 时钟树

```
HSE (外部晶振)
  └─ PLL
      ├─ SYSCLK = 170 MHz
      │   ├─ ADC12/345 (170 MHz)
      │   ├─ I2C1/2 (170 MHz)
      │   └─ FLASH (需 6 wait states)
      │
      ├─ HCLK = 170 MHz (AHB)
      │   └─ DMA1/2
      │
      ├─ PCLK1 = 85 MHz (APB1, 2 分频)
      │   ├─ FDCAN1 (85 MHz)
      │   ├─ TIM2/3/4/5
      │   └─ USART2/3
      │
      └─ PCLK2 = 85 MHz (APB2, 2 分频)
          ├─ TIM1/16
          ├─ USART1
          └─ SPI
```

### 3.3 定时器使用

| 定时器 | 时钟源 | 用途 | 关键特性 |
|--------|-------|------|---------|
| **TIM1** | PCLK2 (170MHz, 2倍频) | 三相 PWM 输出 | 15-60kHz, 死区控制 |
| **TIM2** | PCLK1 (85MHz) | 辅助定时/正交解码/BiSS-C | 32-bit 计数器 |
| **TIM3** | PCLK1 (85MHz) | 辅助定时/正交解码/BiSS-C | 16-bit 计数器 |
| **TIM4** | PCLK1 (85MHz) | 辅助定时/正交解码/BiSS-C | 16-bit 计数器 |
| **TIM5** | PCLK1 (85MHz) | 辅助定时/正交解码 | 32-bit 计数器 |
| **TIM16** | PCLK2 | 与 TIM1 共享中断向量 | — |
| **LPTIM1** | PCLK1 | ADC 同步触发 | 低功耗定时器 |

**PWM 同步机制**: TIM1 更新事件 → DMA 触发 LPTIM1 → LPTIM1_OUT 触发所有 ADC 同步采样。

### 3.4 ADC 配置

5 个 ADC 协同工作,实现同步采样:

| ADC | 通道 | 信号 | 时钟 | 用途 |
|-----|------|------|------|------|
| ADC1 | CH1 | 相电流 1 (U) | SYSCLK/170MHz | FOC 换相 |
| ADC2 | CH2 | 相电流 2 (V) | SYSCLK/170MHz | FOC 换相 |
| ADC3 | CH3 | 相电流 3 (W) | SYSCLK/170MHz | FOC 换相 |
| ADC4 | CH4 | 温度/模拟 | SYSCLK/170MHz | 温度监测 |
| ADC5 | CH5 | 母线电压 | SYSCLK/170MHz | 电压监测 |

**采样时序**: 由 LPTIM1 外部触发,所有 ADC 在 PWM 导通期间的稳定窗口内同步转换。

### 3.5 通信接口

| 接口 | 引脚 (以 r4.11 为例) | 速率 | 用途 |
|------|---------------------|------|------|
| **FDCAN1** | PA_11 (RX), PA_12 (TX) | 1M/5M bps | CAN-FD 总线 |
| **SPI1** | PA_5/6/7 | 最高 10MHz | DRV8323 栅极驱动配置 |
| **SPI2** | 辅助端口 | — | AS5047P / 外部编码器 |
| **I2C1/2** | 辅助端口 | 最高 1MHz | 外部编码器 (AS5048B 等) |
| **USART1/2/3** | 辅助端口 | 最高 10Mbps | 串行编码器 / UART 通信 |

### 3.6 DMA 使用

| DMA | 用途 |
|-----|------|
| **DMA1** | ADC 数据搬运, UART RX/TX, SPI 编码器读取 |
| **DMA2** | ADC 数据搬运, LPTIM1 触发, SPI 传输 |
| **DMAMUX1** | DMA 请求多路复用 |

### 3.7 特殊外设

| 外设 | 用途 |
|------|------|
| **CORDIC** | 硬件三角函数计算,加速 FOC 中的 sin/cos 运算 |
| **FMAC** | 滤波器数学加速模块 |
| **SYSCFG** | GPIO 中断路由 |

### 3.8 引脚分配总表 (r4.11)

| 引脚 | 功能 | 外设 |
|------|------|------|
| PA_0/1/2 | PWM1/2/3 输出 | TIM1_CH1/2/3 |
| PA_3 | DRV8323 Enable | GPIO |
| PA_5/6/7 | DRV8323 SPI (SCK/MISO/MOSI) | SPI1 |
| PA_8 | VSENSE (母线电压) | ADC5 |
| PA_9 | TSENSE (板温度) | ADC4 |
| PA_11/12 | CAN-FD RX/TD | FDCAN1 |
| PB_0/1/2 | 相电流 1/2/3 | ADC1/2/3 |
| PB_6/7 | DRV8323 Fault / HiZ | GPIO |
| PB_11 | AS5047P CS | GPIO |
| PC_4 | DRV8323 CS | GPIO |
| PC_6/14/15 | LED / Debug | GPIO |
| PF_0/1 | Debug LED / Power LED | GPIO |

## 5. 关节集成适用性

### 5.1 适用场景评估

| 关节类型 | 适用性 | 备注 |
|---------|--------|------|
| 旋转关节 | 非常适合 | 原生设计目标 |
| 无框力矩电机集成 | 理想 | 可直接嵌入关节模组 |
| 谐波/行星减速关节 | 适合 | 支持减速比配置 |
| 轻中型负载 (<2kW) | 适合 | 覆盖大部分协作机器人场景 |
| 人形机器人关节 | 适合 | 已被多个开源项目采用 |
| 超大功率 (>2kW) | 不适合 | 超出硬件限制 |
| 高压系统 (>54V) | 不适合 | 超出电压范围 |

### 5.2 集成前必须确认的参数

#### 机械集成

```
控制板尺寸:
  r4.11: 46×53mm
  c1:    38×38×9mm
  n1:    46×46×8mm
  x1:    56×56×10mm

编码器安装要求:
  - AS5047P 需要轴上安装
  - 径向磁铁固定在电机轴上
  - 气隙 1-2mm,对准精度 ±0.5mm
```

#### 电气匹配

| 参数 | 检查项 |
|------|--------|
| 供电电压 | 10-44V (r4.11), 10-54V (n1/x1) |
| 电机功率 | 不超过对应型号峰值 |
| 电流需求 | 持续电流 ≤ 额定值 |
| 电机类型 | 必须为三相无刷 (BLDC/PMSM) |

#### 软件配置

```python
# 必须配置的关键参数
servo.pid_position.kp = ?           # 位置环 P 增益
servo.pid_position.ki = ?           # 位置环 I 增益
servo.max_current_A = ?             # 电流限制
motor_position.rotor_to_output_ratio = ?  # 减速比

# 校准流程
python3 -m moteus.moteus_tool --target 1 --calibrate
```

### 5.3 典型集成方案

**方案 A: 一体化关节模组**

```

│  ┌─────────────────────────────┐  │
│  │  moteus 控制板              │  │

│  │  - 三相线直连               │  │
```

**方案 B: 外置控制器**

```
┌──────────────┐   CAN-FD   ┌────────────────┐

```


## 6. 硬件打样指南

### 6.1 设计文件清单

| 型号 | 设计工具 | 文件 | 成熟度 |
|------|---------|------|--------|
| r4.11 | Eagle CAD | .sch + .brd + .lbr | 成熟 (多次迭代) |
| n1 r1.3 | Eagle CAD | .sch + .brd + .lbr + 3D STEP | 生产验证 |
| c1 r1.2 | KiCad | .kicad_pcb + .kicad_sch + 3D STEP | 生产验证 |
| x1 r1 | KiCad | .kicad_pcb + .kicad_sch | 生产验证 |

### 6.2 打样前准备工作

#### 6.2.1 生成 Gerber 文件

仓库中不包含 Gerber 文件,需要从原始设计文件导出:

**Eagle CAD (r4.11, n1)**:
1. 打开 .brd 文件
2. 使用 CAM Processor 加载标准 Gerber 输出脚本
3. 导出各层 Gerber (RS-274X 格式)
4. 导出 Excellon 钻孔文件

**KiCad (c1, x1)**:
1. 打开 .kicad_pcb 文件
2. File → Plot → 生成 Gerber
3. 生成钻孔文件
4. 可选: 生成 BOM 和坐标文件

#### 6.2.2 生成 BOM

使用仓库中的 `bom.ini` 配置 (以 KiCad 为例):
1. Tools → Generate BOM
2. 确认所有元器件有明确的 MPN (制造商零件号)
3. 核实关键器件的可采购性

#### 6.2.3 PCB 制造参数

| 参数 | 规格 |
|------|------|
| 层数 | 4 层 |
| 板厚 | 1.6mm (标准) |
| 铜厚 | 外层 1oz, 内层 0.5oz (功率部分可能需要 2oz) |
| 最小线宽/间距 | 6-8 mil |
| 最小过孔 | 0.3mm 孔径 / 0.6mm 焊盘 |
| 阻抗控制 | CAN-FD 信号线需要 100Ω 差分阻抗 |
| 表面处理 | HASL 或 ENIG (推荐 ENIG) |
| 阻焊颜色 | 任意 |

### 6.3 PCB 厂商选择

| 厂商 | 特点 | 适合场景 |
|------|------|---------|
| 嘉立创 (JLCPCB) | 性价比高,支持 SMT 一条龙 | 小批量打样 |
| 捷配 (ALLPCB) | 快速交货 | 紧急打样 |
| PCBWay | 品质好,支持复杂板 | 中批量 |
| 华秋 (HQCHIP) | 国内品质较好 | 品质优先 |

### 6.4 SMT 贴片注意事项

- QFN-48 封装 (STM32G4) 需要钢网和回流焊
- 功率 MOSFET 散热焊盘需确保良好焊接
- 手工焊接难度较高,建议 SMT 贴片
- 焊接后需要进行目检和必要的电气测试

### 6.5 固件烧录

1. 通过 SWD 接口 (PA13/SWDIO, PA14/SWCLK) 连接调试器
2. 使用 ST-Link 或 J-Link 烧录固件
3. 首次烧录后需要通过 `moteus_tool --calibrate` 进行电机校准

### 6.6 风险提示

| 风险 | 说明 | 建议 |
|------|------|------|
| 元器件缺货 | STM32G4 等可能交期长 | 提前备货 |
| 设计缺陷 | 开源设计可能有未发现问题 | 先小批量验证 |
| 高压安全 | 10-54V 直流,功率可达千瓦级 | 注意绝缘和防护 |
| 校准难度 | 电机控制需要专业校准 | 参考官方文档 |

### 6.7 推荐方案

| 需求 | 建议 |
|------|------|
| 学习/原型验证 | 购买成品板,节省时间 |

## 7. CAN-FD 通信协议

### 7.1 物理层

| 参数 | 规格 |
|------|------|
| 物理层 | CAN-FD (ISO 11898-2:2016) |
| 仲裁位率 | 1 Mbps |
| 数据位率 | 5 Mbps (BRS 模式) |
| 帧格式 | CAN-FD Extended |
| 最大数据长度 | 64 bytes |
| 拓扑 | 总线型,两端 120Ω 终端电阻 |

### 7.2 CAN ID 格式

```
16-bit ID 结构:
┌─────────────────┬─────────────────┐
│   高 8 位        │   低 8 位        │
│   Source         │   Destination   │
│                  │                  │
│ bit 15: 回复请求 │ bit 6-0: 设备 ID │
│ bit 14-8: 源地址 │                  │
└─────────────────┴─────────────────┘

示例:
- 0x8001: 源 0 → 设备 1, 要求回复 (bit 15 = 1)
- 0x0100: 源 1 → 设备 0, 不要求回复
- 0x0000: 广播地址
```

设备 ID 范围: 1-127 (0 为广播地址)。

### 7.3 子帧结构

每个 CAN-FD 帧包含一个或多个子帧,类型如下:

| 类型码 | 操作 | 数据类型 |
|--------|------|---------|
| 0x00 | 写入 | int8 |
| 0x04 | 写入 | int16 |
| 0x08 | 写入 | int32 |
| 0x0c | 写入 | float32 |
| 0x10 | 读取 | int8 |
| 0x14 | 读取 | int16 |
| 0x18 | 读取 | int32 |
| 0x1c | 读取 | float32 |
| 0x20 | 回复 | int8 |
| 0x24 | 回复 | int16 |
| 0x28 | 回复 | int32 |
| 0x2c | 回复 | float32 |
| 0x30/31 | 写/读错误 | — |
| 0x50 | NOP | — |

**子帧格式**:

```
写入子帧:
┌──────┬───────────┬───────────┬───────────────────┐
│ 类型 │ 寄存器数量 │ 起始寄存器 │ N × 数据值         │
│      │ (varuint) │ (varuint) │                    │
└──────┴───────────┴───────────┴───────────────────┘

读取子帧:
┌──────┬───────────┬───────────┐
│ 类型 │ 寄存器数量 │ 起始寄存器 │
│      │ (varuint) │ (varuint) │
└──────┴───────────┴───────────┘

回复子帧:
┌──────┬───────────┬───────────┬───────────────────┐
│ 类型 │ 寄存器数量 │ 起始寄存器 │ N × 数据值         │
│      │ (varuint) │ (varuint) │                    │
└──────┴───────────┴───────────┴───────────────────┘

注: 寄存器数量的低 2 位可以编码在类型码的最低 2 位中,
    实现 1-4 个寄存器的紧凑编码。
```

**varuint 编码**: 可变长度无符号整数,每个字节的低 7 位为数据,最高位表示是否还有后续字节。最大 5 字节表示一个 uint32。

## 8. 总线速率与扩展性

### 8.1 当前配置

基于固件代码确认:

```c
// CAN-FD 时钟源
FDCAN 时钟 = PCLK1 = 85 MHz

// 位率配置
仲裁段 (Nominal)  = 1 Mbps
数据段 (Data/BRS) = 5 Mbps

// 发送器延迟补偿 (TDC)
tdc_offset = 13   → 13 / 85MHz ≈ 152ns
tdc_filter = 2    → 2 / 85MHz ≈ 23ns
```

### 8.2 速率提升分析

#### 8.2.1 MCU 外设能力

| 参数 | 当前值 | STM32G4 FDCAN 最大值 | 结论 |
|------|--------|---------------------|------|
| 仲裁位率 | 1 Mbps | 1 Mbps | 已达标准上限 |
| 数据位率 | 5 Mbps | 8 Mbps | 理论可提升 60% |
| 外设时钟 | 85 MHz | 85 MHz | 受限于系统时钟 |

#### 8.2.2 物理层限制

CAN-FD 数据位率受以下因素制约:

| 限制因素 | 说明 | 对 8Mbps 的影响 |
|---------|------|----------------|
| 传播延迟 | 收发器 + 线缆 + 节点 | 需要更精确的 TDC |
| 信号衰减 | 线缆长度导致高频衰减 | 最大线缆长度降至 2m |
| 反射 | 阻抗不匹配导致的信号反射 | 对终端匹配要求更高 |
| 电磁干扰 | 高速信号的 EMI | 需要屏蔽措施 |

#### 8.2.3 性能评估

| 速率 | 单帧时间 (64B) | 理论帧率 | 有效带宽 | 推荐线缆长度 |
|------|---------------|---------|---------|-------------|
| 1 Mbps (Classical) | ~1ms | ~1000 | ~8 KB/s | ≤40m |
| 5 Mbps (当前) | ~125μs | ~8000 | ~250 KB/s | ≤5m |
| 8 Mbps (理论最大) | ~80μs | ~12500 | ~400 KB/s | ≤2m |

### 8.3 实际需求评估

```
典型机器人控制需求:

单轴 @ 1kHz:
  8 字节/帧 × 1000 帧/秒 = 8 KB/s

12 轴 @ 1kHz:
  8 字节/帧 × 12 × 1000 = 96 KB/s

当前 5Mbps 提供: ~250 KB/s
12 轴利用率: 96/250 ≈ 38%
```

**结论**: 5Mbps 对于绝大多数机器人控制场景已绰绰有余。

### 8.4 扩展方案

当 5Mbps 确实不足时,可考虑以下方案:

| 方案 | 优点 | 缺点 |
|------|------|------|
| 多 CAN 总线 | 线性扩展,保持稳定性 | 需要更多硬件和软件复杂度 |
| 批量读写 | 提高协议效率 | 减少延迟 |
| 混合通信 | UART/Ethernet 承载大数据 | 系统集成复杂度增加 |

## 9. 通信协议演进趋势: EtherCAT vs CAN-FD

### 9.1 核心性能对比

| 特性 | CAN-FD (moteus) | EtherCAT |
|------|----------------|----------|
| 带宽 | 5 Mbps | 100 Mbps |
| 实时性 | 软实时 (μs 级抖动) | 硬实时 (<1μs 抖动) |
| 同步精度 | 10-100 μs | <1 μs |
| 网络拓扑 | 总线型 (共享带宽) | 线型/树型 (逐站处理) |
| 节点数量 | 实际 20-30 | 实际 100+ |
| 控制周期 | 典型 1kHz | 可达 10-50kHz |
| 最大距离 | 5-40m | 100m (无交换机) |
| 功能安全 | 无原生支持 | FSoE (SIL3/PL e) |
| 互操作性 | 自定义协议 | CiA 402 标准化 |

### 9.2 EtherCAT 的核心优势

#### 9.2.1 确定性实时性能

EtherCAT 的 "processing on the fly" 机制使帧在每个从站停留时间极短 (<1μs),整个网络的通信抖动可以控制在 1μs 以内。这对高精度轨迹跟踪至关重要。

CAN-FD 的 CSMA/CA 仲裁机制引入了不确定性,在多节点竞争总线时,帧延迟可达数十微秒。

#### 9.2.2 分布式时钟 (DC)

EtherCAT 的分布式时钟机制使所有从站在同一时刻执行控制循环,同步误差 <1μs。这对多轴协同运动 (如并联机器人、CNC) 是关键需求。

CAN-FD 网络中各节点的响应时间不同,累积延迟可达数百微秒,导致多轴不同步。

#### 9.2.3 带宽效率

EtherCAT 单个以太网帧可包含所有从站的数据,帧处理在从站间流水线传递,带宽利用率接近 100%。

CAN-FD 的总线共享机制下,所有节点竞争带宽,且每帧开销较大,实际有效数据率约为标称速率的 74%。

#### 9.2.4 功能安全

EtherCAT 通过 FSoE (Fail Safe over EtherCAT) 协议支持功能安全,可达 SIL3/PL e 等级,支持安全扭矩关闭 (STO)、安全停止 (SS1/SS2)、安全速度 (SLS) 等安全功能。

CAN-FD 本身不具备功能安全协议,在人机协作等需要安全认证的场合需要额外的安全系统。

### 9.3 CAN-FD 的优势领域

EtherCAT 并非在所有场景下都是最佳选择:

| 场景 | CAN-FD 优势 | 原因 |
|------|------------|------|
| 成本敏感 | 硬件成本低 50%+ | 无需专用 EtherCAT 从站芯片 |
| 小型系统 | 简单可靠 | 总线拓扑简单,无需配置 |
| 开源生态 | 完全透明可修改 | 适合研究和快速迭代 |
| 恶劣环境 | 抗干扰能力强 | CAN 物理层更健壮 |
| 长距离 | 40m 以上仍有优势 | EtherCAT 需要交换机中继 |
| 低功耗 | 功耗更低 | 适合电池供电设备 |

### 9.4 行业应用分布

| 领域 | 主流选择 | 原因 |
|------|---------|------|
| 工业机器人 (6轴+) | EtherCAT | 多轴同步、高精度 |
| CNC 机床 | EtherCAT | 多轴联动、μm 精度 |
| 半导体设备 | EtherCAT | 纳米定位、超高速 |
| 包装/注塑机械 | EtherCAT | 高速同步 |
| 协作机器人 | EtherCAT/CAN-FD | 取决于精度需求 |
| 人形机器人 (原型) | CAN-FD | 快速开发、开源生态 |
| 四足机器人 | CAN-FD | 成本、重量敏感 |
| 服务机器人 | CAN-FD | 成本优先 |
| 外骨骼 | CAN-FD | 低功耗、轻量化 |

### 9.5 选型建议

```
选择 EtherCAT 当:
  ✓ 需要 <1μs 的多轴同步精度
  ✓ 控制频率 >1kHz
  ✓ 轴数 >6
  ✓ 需要功能安全认证 (SIL/PL)
  ✓ 工业量产产品
  ✓ 需要与第三方设备互操作

选择 CAN-FD 当:
  ✓ 成本是主要约束
  ✓ 轴数较少 (<6)
  ✓ 控制频率 ≤1kHz
  ✓ 研究/原型阶段
```
